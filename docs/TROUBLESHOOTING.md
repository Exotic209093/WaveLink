## 1. Installation Issues

### Extension doesn't appear after Load Unpacked

**Symptom:** After clicking "Load unpacked" and selecting the `dist/` folder, WaveLink doesn't appear in the extensions list or toolbar.

**Causes and fixes:**

1. **Selected the wrong folder.** You must select the `dist/` folder, not the repo root. The `dist/` folder should contain `manifest.json`, `background/`, `popup/`, `app/`, and `content/` folders. Verify with your file browser before loading.

2. **Build hasn't run.** The `dist/` folder is generated by the build step. Run `npm run build` first.

3. **Build errors.** Check the terminal for webpack errors. Common causes: missing `node_modules` (run `npm install`) or TypeScript errors (run `npm run typecheck` to identify them).

4. **Chrome requires a reload.** After loading, Chrome sometimes needs a full restart. Close and reopen Chrome.

---

### Extension loads but icon doesn't appear in toolbar

Chrome may hide the extension. Click the **puzzle-piece icon** in the Chrome toolbar, find WaveLink, and click the **pin icon** to pin it to the toolbar.

---

### "Manifest version 2 is deprecated" warning

WaveLink uses Manifest V3. If you see this warning, you have loaded the wrong folder. Ensure you loaded `dist/` and that `dist/manifest.json` contains `"manifest_version": 3`.

## 2. Org Connection Problems

### "No Salesforce org detected" in the popup

**Symptom:** Opening the WaveLink popup shows "No org detected" or an empty org switcher.

**Checklist:**

- [ ] You are on a Salesforce page (URL contains `.salesforce.com`, `.force.com`, `.lightning.force.com`, or `.my.salesforce.com`)
- [ ] You are **logged in** — Salesforce shows your username in the top bar
- [ ] The tab finished loading (spinner is gone)
- [ ] The content script is active — right-click the page, choose Inspect, open Console. You should see a `[WaveLink] Content script loaded` message.
- [ ] WaveLink has permission for this domain — go to `chrome://extensions`, click WaveLink's "Details", and check "Site access" includes your org's domain.

**Fix:** Reload the Salesforce tab after installing the extension. Content scripts are not injected into tabs that were already open when the extension was installed.

---

### Org shows "Disconnected" after reopening Chrome

**Cause:** Chrome sometimes clears session cookies when the browser closes, which invalidates the stored session token.

**Fix:** Log into Salesforce again in the browser tab. Open the WaveLink popup and click **Refresh** on the org, or remove and re-add the org.

---

### Wrong org is shown as active

**Fix:** Click the org name in the WaveLink header to open the **Org Switcher** and select the correct org. Each browser tab maintains its own context — if you have multiple Salesforce tabs open, pin the full app to a specific tab using the **"Pin to tab"** option.

## 3. Authentication Errors

### `401 Unauthorized` or `INVALID_SESSION_ID`

**Cause:** The session token (`sid` cookie) has expired or been invalidated (e.g., the Salesforce admin ended your session, or you logged out).

**Fix:**
1. Go to the Salesforce tab and reload it — this re-establishes the session
2. In WaveLink, open the Org Switcher and click **Refresh** on the affected org
3. If the error persists, remove the org and reconnect it

---

### `403 Forbidden` or `INSUFFICIENT_ACCESS`

**Cause:** Your Salesforce user account does not have permission to access the requested object or field.

**Fix:** This is a Salesforce permission issue, not a WaveLink issue. Check:
- Object-level security (OLS) — can your profile/permission set read/write this object?
- Field-level security (FLS) — are all mapped fields visible to your user?
- Record sharing — for updates/deletes, does your user own or have sharing access to these records?

---

### `EXCEEDED_ID_LIMIT` or `REQUEST_LIMIT_EXCEEDED`

**Cause:** You have hit the org's daily API call limit.

**Fix:**
- Check the **API Usage Dashboard** screen in WaveLink for current consumption
- Wait until the limit resets (daily, at midnight GMT)
- Contact your Salesforce admin to request a limit increase or purchase additional API calls

## 4. Push Failures

### All records fail with the same error

**Common errors and fixes:**

| Error | Cause | Fix |
|-------|-------|-----|
| `REQUIRED_FIELD_MISSING` | A required field has no value | Add the field to your dataset or set a default in the field mapping |
| `FIELD_INTEGRITY_EXCEPTION` | A lookup field references a non-existent record ID | Verify the IDs exist in the target org |
| `DUPLICATE_VALUE` | A unique field already has this value | Check for duplicates in your dataset or use Upsert instead of Insert |
| `STRING_TOO_LONG` | A text value exceeds the field's length limit | Truncate the value in the Data Cleanser before pushing |
| `INVALID_FIELD` | A field in your mapping doesn't exist on the target object | Check the field API name — it may differ between orgs |
| `FIELD_FILTER_VALIDATION_EXCEPTION` | A validation rule rejected the record | Review the org's validation rules for this object |

---

### Some records succeed, some fail

WaveLink captures partial success. After a push:

1. View the **Push History** screen — failed records are grouped by error message
2. Click **Retry Failed** to create a new dataset with only the failed records
3. Fix the data issue (use the Data Cleanser if needed) and push again

---

### Push stops partway through with no error

**Cause:** The Chrome background service worker was terminated by Chrome (MV3 service workers are ephemeral). This is most common during long REST pushes.

**Fix for REST pushes:** Click **Retry Failed** — WaveLink records which records were successfully pushed, so retrying only sends the unprocessed ones.

**Fix for Bulk API pushes:** The job continues running in Salesforce even if the service worker is terminated. Reopen WaveLink — the background script re-polls the job status on startup and reports the final result.

---

### Push appears stuck at "Processing..."

**For REST pushes:** If no progress after 2 minutes, check the service worker console (see [Getting Debug Information](#12-getting-debug-information)). The worker may have been terminated.

**For Bulk API pushes:** Bulk jobs can take several minutes for large datasets. The poll interval is 5 seconds. If stuck for more than 10 minutes, check the Salesforce Setup → Bulk Data Load Jobs page to see the job status directly.

## 5. Bulk API Issues

### Bulk job stuck in "Open" or "UploadComplete" state

**Cause:** The job was not closed properly (service worker terminated during upload).

**Fix:** WaveLink automatically closes jobs it creates. If a job is stuck in Salesforce, close it manually from **Setup → Bulk Data Load Jobs → [Job ID] → Abort Job**.

---

### Bulk job fails with `InvalidBatch`

**Cause:** The CSV uploaded to the Bulk API has a formatting issue — mismatched column counts, invalid characters, or encoding issues.

**Fix:**
1. Export your data from WaveLink as CSV
2. Open the CSV and check for: rows with different column counts, special characters (curly quotes, em-dashes), or mixed line endings
3. Clean the data in the Data Cleanser and re-push

---

### Bulk API used for small datasets

**Cause:** The auto-switch threshold is 2,000 records. If you're seeing Bulk API used for smaller datasets, check if you intentionally set a custom threshold.

## 6. Query Errors

### `MALFORMED_QUERY` in the SOQL editor

**Cause:** The generated SOQL has a syntax error.

**Fix:**
1. Switch to the raw SOQL text view and identify the error
2. Common issues: reserved words used as field names (wrap in quotes), unsupported functions, invalid field paths in relationship queries
3. The autocomplete parser helps prevent this — use the structured builder mode

---

### Query returns no results when records exist

**Checklist:**
- [ ] Check the WHERE clause — filters may be too restrictive
- [ ] Verify your user has sharing access to the records
- [ ] Check the LIMIT clause — it may be set lower than expected
- [ ] Some objects require special query conditions (e.g., `IsDeleted = true` for recycle bin records)

---

### Query times out

**Cause:** The query is too broad (no selective filter on an indexed field) or the org has a large data volume.

**Fix:**
1. Add a WHERE clause that filters on an indexed field (ID, CreatedDate, external ID fields)
2. Reduce the LIMIT
3. Use the `queryAll()` endpoint only when querying deleted records

---

## 7. Import / Export Problems

### CSV import produces garbled text

**Cause:** Character encoding mismatch. Salesforce and WaveLink expect UTF-8.

**Fix:**
1. Open your CSV in a text editor
2. Save it explicitly as UTF-8 (in Notepad: File → Save As → Encoding: UTF-8 without BOM)
3. Re-import the saved file

---

### Excel import loses leading zeros (e.g., zip codes become numbers)

**Cause:** Excel stores numeric-looking values as numbers, dropping leading zeros.

**Fix:**
1. In Excel, format the affected column as Text before saving
2. Or use CSV export from your source system instead of Excel
3. Or use the Data Cleanser's transform step to pad values with leading zeros after import

---

### Export file is empty or missing columns

**Checklist:**
- [ ] Check the **Column Selector** — deselected columns are excluded from export
- [ ] Ensure the dataset has rows (run a query or import data first)
- [ ] For Excel export, check if the file opens correctly — it may have been flagged by antivirus

---

### "File too large to import"

**Cause:** WaveLink's current file parser loads the entire file into browser memory. Files over ~10 MB can cause memory issues.

**Fix:**
1. Split the file into smaller chunks (< 10 MB each)
2. Use a tool like `split` (Linux/Mac) or the "Text to Columns" split feature
3. Streaming large file support is planned in a future release

## 8. UI and Display Issues

### WaveLink popup is blank / white

**Cause:** A JavaScript error in the popup script.

**Fix:**
1. Right-click the WaveLink icon → Inspect popup
2. Check the Console tab for errors
3. Common cause: extension was built with errors; run `npm run build` and check for compilation errors

---

### Dark mode not applying correctly

**Fix:**
1. Open **Settings → Appearance → Theme** and toggle between Light/Dark/Auto
2. If "Auto" is selected, it follows your OS preference — change OS dark mode setting to verify

---

### Side panel appears on the wrong side or behind Salesforce elements

**Cause:** Some Salesforce pages use high `z-index` values that overlap the panel.

**Fix:** The panel uses a shadow DOM to isolate its styles. If still overlapping, try resizing the panel — drag the left edge. You can also open the **Full App** in a separate tab as a workaround.

---

### Command palette (`Ctrl+K`) doesn't open

**Cause:** The keyboard shortcut may have been rebound or conflicted with a Salesforce shortcut.

**Fix:**
1. Click the WaveLink icon → Open Full App
2. Navigate to Settings → Keyboard Shortcuts
3. Reset the command palette shortcut or assign a new one

---

## 9. Performance Issues

### WaveLink is slow to load schema / field lists

**Cause:** The schema cache is cold (first load, or cache was cleared).

**Fix:** After the first load, schema is cached for 30 minutes. Subsequent loads are instant. If consistently slow, check your org's API response times — the **API Usage Dashboard** shows limit consumption.

**Tip:** Increase the schema cache TTL in Settings to reduce re-fetching.

---

### Large push operations (10,000+ records) are slow

**Expected behaviour:** Large datasets automatically use Bulk API 2.0, which processes asynchronously on Salesforce's servers. WaveLink polls every 5 seconds. A 10,000-record insert typically takes 1–3 minutes depending on org load and triggers.

**To speed up:** Disable Salesforce automation (workflow rules, flows, triggers) for the target object during testing in sandboxes, if permitted.

---

### Browser tab freezes during large file import

**Cause:** Parsing a large file (close to the 10 MB limit) is CPU-intensive.

**Fix:** WaveLink uses Papa Parse in streaming mode for CSV. For Excel files, the entire file is loaded into memory — use CSV instead for large datasets.

---

## 10. Storage and Data Issues

### "Storage quota exceeded" error

**Cause:** `chrome.storage.local` has a default 5 MB quota. Large schema caches, push history, or undo data can fill this.

**Fix (in order):**
1. **Settings → Security → Clear Undo History** — clears rollback data (typically the largest store)
2. **Settings → Schema → Clear Schema Cache** — clears cached field metadata
3. **Settings → History → Clear Push History** — clears the push log
4. Reduce the push history limit in Settings (default: 100 entries)

---

### Queries / templates disappeared

**Cause:** `chrome.storage.local` can be cleared if Chrome's profile data is reset, or if you used the "Clear browsing data" option with "Hosted app data" checked.

**Fix / Prevention:**
1. Export your query library and templates as JSON bundles from the **Query** and **Templates** screens
2. Store backups in a safe location
3. Re-import the bundles after restoring

---

### Org list is empty after Chrome update

**Cause:** Some Chrome updates reset extension storage or clear cookies.

**Fix:** Reconnect your orgs — open each in a Salesforce tab and use the popup to connect. Schema cache and push history are separate from the org list, so they may still be present.

---

## 11. Extension Lifecycle Issues

### Service worker keeps restarting

**Expected behaviour in MV3:** Chrome terminates idle service workers after 30 seconds of inactivity. This is normal. The background script re-initialises its state from `chrome.storage.local` on each restart.

**Impact:** In-flight state is lost when the worker restarts. For REST pushes, use **Retry Failed**. For Bulk API pushes, the job continues in Salesforce and WaveLink re-syncs on the next poll.

**If restarting too frequently:** This can indicate a JavaScript error in the background script causing a crash loop. Check the service worker console (see below).

---

### "Receiving end does not exist" errors in console

**Cause:** A message was sent to a UI context (popup, app, or content script) that was closed before the response arrived. This is harmless.

---

## 12. Getting Debug Information

### Service Worker Console (background script errors)

1. Go to `chrome://extensions`
2. Find WaveLink
3. Click **"Service worker"** — this opens DevTools connected to the background script
4. Check the **Console** tab for errors and the **Network** tab for API calls

### Popup Console

1. Right-click the WaveLink toolbar icon
2. Select **"Inspect popup"**
3. DevTools opens attached to the popup

### Content Script Console

1. Open DevTools on a Salesforce page (`F12`)
2. In the Console tab, select the **content script** context from the context dropdown (next to the filter box)
3. WaveLink content script logs are prefixed with `[WaveLink]`

### Collecting a Bug Report

When filing a GitHub issue, please include:
- Chrome version (`chrome://version`)
- WaveLink version (shown in `chrome://extensions`)
- The error message (exact text)
- Steps to reproduce
- The object type and approximate record count (for push issues)
- Service worker console output if relevant (sanitise any sensitive data before sharing)
